# Idea Refining：想法收敛技能

[English README](README.md)

Idea Refining 是一个主要面向 Codex 的纯指令型智能体技能。它会在宿主智能体回答或执行之前，将宽泛、模糊、依赖偏好的请求收拢成最小充分规格。

它的核心是划定边界，而不是进行穷尽式询问。每个问题都必须能够改变范围、内容、实现路线、可靠性、质量或验收标准等下游决策。重复、可推断、时机过早和低影响的问题应被删除。

## 主要能力

- 判断信息缺失是否会实质性改变结果。
- 将任务收拢为一句单点定义。
- 每轮通常询问 3–5 个相互关联的高价值问题；没有足够问题时可以少问。
- 说明每个问题希望确定的决策。
- 用户不知道如何回答时提供容易理解的选项。
- 先利用用户提供的文件、图片、链接和已有规格，避免重复询问。
- 需求达到可交付状态后立即停止。
- 为宿主智能体生成可执行上下文。
- 访谈达到三轮时，额外生成人类可读的完整需求文档。

## 不负责的内容

- 不对简单事实问题进行多余询问。
- 不强迫所有任务完成固定清单。
- 除非用户明确说“直接回答”，否则不会在未获确认时执行最终任务。
- 不对高风险领域结论提供专业正确性保证。
- 第一版不包含专业领域模块和脚本。

## 工作原理

技能按照以下循环工作：

1. 检查对话和用户提供的材料。
2. 将当前请求压缩成一句任务定义。
3. 识别真正会影响交付的信息缺口。
4. 删除重复、可推断、时机过早或可安全使用默认值的问题。
5. 询问价值最高的问题，并更新任务边界。
6. 当关键决策已经确认或明确采用假设时停止。
7. 生成不包含作废答案和访谈历史的干净交接内容。

技能会展示近似完整度。完整度只表示需求是否被充分定义，不代表最终结论一定安全或正确。

## 在 Codex 中安装

Codex 支持项目级和用户级技能。

只在一个项目中使用时，将整个目录复制到：

~~~text
<项目目录>/.agents/skills/idea-refining/
~~~

希望在个人的所有项目中使用时，复制到：

~~~text
$HOME/.agents/skills/idea-refining/
~~~

复制后，SKILL.md 必须位于 idea-refining 目录根部。Codex 会根据技能名称和描述发现技能，并在任务匹配时加载完整指令。

当前安装和发现规则可参考 [Codex 官方技能文档](https://learn.chatgpt.com/docs/build-skills)。

## 使用方式

显式调用：

~~~text
$idea-refining 帮我定义一个用于点评学校及周边餐饮的网站。
~~~

~~~text
$idea-refining 我想写一篇文章，但还没有确定形式和重点。
~~~

技能已经允许隐式调用。当宽泛请求缺少会显著影响结果的决策时，Codex 可以自动选择本技能。

下面这样的简单请求不应触发技能：

~~~text
今天天气怎么样？
~~~

## 用户控制指令

用户可以说：

- **直接回答**：停止收敛，由宿主智能体继续处理原始任务。
- **跳过**：暂时保留当前未知项。
- **使用推荐方案**：接受技能提出的默认选项。
- **返回修改**：替换之前的决定。
- **重新开始**：清空本次收敛状态并重新访谈。
- **先生成方案，不要执行**：只接收交接内容，不开始实际工作。

其他语言中的同义表达同样有效。

## 输出方式

如果需求在一至两轮内达到可交付状态，技能只生成精简的智能体执行上下文。

如果访谈达到三轮，则生成：

1. 人类可读的完整需求文档；
2. 精简的智能体执行上下文。

如果达到最终续问上限时仍然缺少重要信息，技能会输出标记为“尚未具备可靠执行条件”的文档，并列出未解决的关键问题。

## 收拢示例

宽泛的写作请求：

~~~text
给我写一篇文章。
~~~

可能被收拢为：

~~~text
为高中生读者写一篇约 3000 字的现实主义短篇小说，以当代沿海小城为舞台，围绕一名学生在家庭期待与个人理想之间的冲突展开，整体克制而温暖，以开放式结局收束。
~~~

宽泛的软件请求：

~~~text
给我写一个点评网站。
~~~

可能被收拢为：

~~~text
构建一个面向本校学生的食堂及周边餐饮点评网站。用户能够按位置和餐饮类型浏览店铺，进行多维评分、文字评论和图片上传；系统需要内容审核、可靠的数据存储、异常处理、测试和本地部署说明。最终交付必须能够完成完整点评流程，而不只是静态页面。
~~~

具体问题必须与交付深度匹配。概念方案不应被数据库和部署问题拖累；要求生产可用的软件则必须讨论视觉效果之外的可靠性。
